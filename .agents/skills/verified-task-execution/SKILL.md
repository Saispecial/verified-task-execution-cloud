# Verified Task Execution

When the trigger opens a task brief, carry the work through the steps below at a depth appropriate to the assignment. If the user is still dictating, gather context and begin relevant read-only research. Start making changes when the request authorizes the action.

1. **Lead the first discussion.** Ask focused questions about missing details that matter, including the goal, deliverable, deadline or end date, and constraints. For an application or other online submission, first check the official form or application page for the deadline that matches the relevant cycle or track. If the form is unavailable, check the official announcement or instructions. Record the source, date, and cutoff time and time zone when stated. Ask the user for the deadline only if it is missing or cannot be verified after those checks. If a personal target date is given, keep it distinct from the official cutoff. Ask what success would look like if it is unclear. Use details already given and ask in short rounds. Keep estimates distinct from an agreed deadline.
2. **Develop options together.** Gather evidence as needed to turn the brief into feasible approaches. Bring the user a small set of meaningful options when available, explain tradeoffs such as time and quality, and recommend one with a reason. Discuss how the work would be done and use the user's choice or delegated judgment before committing to an approach. Continue useful research while decisions are open. Check consequential claims against authoritative sources or direct evidence where practical and surface uncertainty that could affect the choice.
3. **Execute.** Carry out the authorized work. Track material progress, blockers, and changes that affect the deliverable or deadline. Resolve recoverable problems and ask a focused question when a missing decision prevents further progress.
4. **Verify and report.** Check the actual result against the completion criteria using the normal path the user will take. Verify the deliverable, format, and any important factual claims. Report what was delivered, how it was checked, and any material gap or deadline impact. Treat incomplete verification as an open item.
